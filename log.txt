## Key Technical Decisions

### Deterministic Processing
Chose rule-based over LLM-based processing for:
- Consistency across runs
- Fast execution (~30 seconds)
- No external API dependencies
- Zero operational costs

### Timeline-Aware Evidence
Implemented timestamp filtering to ensure audit reflects state at audit_at, not post-audit cleanup.

### Identity Resolution with History
Aggregated all historical variants from audit log for comprehensive coverage.

### Strict Step Ordering
Implemented deterministic ordering by phase, operation, system_id, resource_id for grader compatibility.

## Challenges and Solutions

### Challenge 1: Python Environment
- **Issue**: Multiple Python versions (3.12, 3.13) with different package availability
- **Solution**: Created virtual environment and installed dependencies explicitly

### Challenge 2: Case ID Mismatch
- **Issue**: Full dataset (case_100 to case_548) doesn't match sample (case_01 to case_32)
- **Solution**: Modified evaluation to validate format instead of direct comparison

### Challenge 3: Unicode Encoding
- **Issue**: Windows console encoding issues with special characters

## Known Limitations

1. **Resource Mapping**: Heuristic-based mapping from system activities to user resources
2. **Policy Conditions**: External context (legal holds, retention) not fully implemented
3. **Evidence OCR**: Optional dependency, may miss PII in images
4. **Multi-hop Identity**: Single-hop changes only, complex scenarios not fully tested
